*Finding 2:* In the UCE table, `pixelRequestUserAgent` and `attributedCreativeUserAgent` represent the conversion and engagement user agents respectively. Do we have matching user-agent fields in the UDI schema?

Checked LAN clicks (`tracking.adrealtimebiddingclickevent`) and impressions (`tracking.adrealtimebiddingimpressionevent`). Both expose UA in three forms:
- `requestheader.useragent` — raw UA string (browser, version, device hints)
- `device` — parsed `{make, model, os, osversion, devicetype, deviceid}`
- `mobileheader` — `{osname, osversion, devicemodel, ...}` for mobile only

Coverage on click event (partition `2026-05-18-00`, 11.5M rows):
```
requestheader.useragent  100%
device.devicetype        100%   (PHONE / TABLET / CONNECTED_TV)
device.os                 99.97% (Android / iOS / smartcast os / ...)
device.make                0%
device.model               0%
device.osversion           0%
```

So `device` is sparse — only `os` + `devicetype` are populated. The raw `requestheader.useragent` is the only field that carries the full browser/version/exact-device info that UCE's `*UserAgent` varchars hold.

Recommendation: map UCE's `*UserAgent` → `requestheader.useragent`. Use `device.devicetype` / `device.os` only as derived/parsed signals. Thoughts?
